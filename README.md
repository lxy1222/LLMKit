# LLMKit · 大模型工具引导式一键安装器

给**完全的新手**用的 Windows 小工具：把 Claude Code、Codex 这类 AI 编程工具，从"装好"到"能跑通一次"这一段最难的路，变成在浏览器里点几下。

只走**官方 API**，不碰本地模型。

- 只有一套界面：**浏览器**。本地服务只监听 `127.0.0.1`，不对外网开放。
- **不需要管理员权限**，也不需要任何编译器。
- **不内置、不代发、不代充任何 API Key**：本工具只提供各渠道的注册与创建 Key 的入口，Key 始终由你自己创建和保管。

> **现状**：开发中，尚未发布正式版本。核心链路（检测、安装、卸载、配置、启动、还原）都已实测过，但**"在一台干净的机器上从零走一遍"和"真实下载链路"还没有完整验证** —— 见下面的「已知限制」。

---

## 它解决什么问题

新手在这一步通常会卡四件事，本工具就照这四件事设计：

| 卡点 | 这里的做法 |
|---|---|
| 不知道要装什么、从哪装 | 十一个工具按用途排好，每个工具页就是它自己的步骤清单 |
| 装完了不会配、配了不知道对不对 | 每个工具页的「配好渠道和模型」直接照**官方文档原文**给步骤；配完能「验证可用性」真的跑一次 |
| 怕把系统改坏、改错了回不去 | 所有改动**只搬不删**：挪到备份区、写进会话日志，随时能一键还原 |
| 命令搞不懂、报错看不懂 | 报错翻译成人话（内置错误映射表），并说明下一步做什么 |

## 支持的十一个工具

界面把它们分成三组。**智能体**是你拿去干活的；**配套工具**自己不调模型，负责把环境备齐或把渠道管起来；**本地模型运行时**让模型跑在你自己机器上。

### 智能体（5 个）

| 工具 | 说明 |
|---|---|
| **Claude Code** | Anthropic 的终端编程助手；官方原生安装器，不需要 Node |
| **Codex CLI** | OpenAI 的终端编程助手；接入用 DeepSeek 官方的一键配置脚本 |
| **OpenCode** | 开源终端编程助手；在它自己的界面里用 `/connect` 配渠道 |
| **Gemini CLI** | Google 的终端编程助手；渠道交给 cc-switch 管 |
| **DeepSeek Harness（dsh）** | DeepSeek 官方出品，自带网页界面；`dsh web` 起来的是浏览器界面 |

### 配套工具（5 个）

| 工具 | 用途 |
|---|---|
| **Node.js** | 多个智能体的运行时（要求 v18+） |
| **Git for Windows** | Claude Code 的部分功能依赖它 |
| **cc-switch** | 图形界面，统一管"用哪个渠道、哪把 key"，再由它去写各智能体的配置 |
| **Python** | 编程运行时；页面里还能查常用第三方库装没装 |
| **PyCharm** | 写 Python 的 IDE |

### 本地模型运行时（1 个）

| 工具 | 用途 |
|---|---|
| **Ollama** | 把开源模型跑在你自己机器上，开一个 `127.0.0.1:11434` 的 OpenAI 兼容接口；不花钱、数据不出本机，代价是占磁盘、吃显存 |

每个工具都有**自己的页面**，都能**单独安装、单独卸载**（不需要"一起补齐"）。

## 界面长什么样

**首页**两块：智能体一组、配套工具一组，每张卡带状态（未安装 / 已安装 / 已安装但有残留）与所需操作入口。

**每个工具一页**（`#/tool/<id>`），页面本身就是步骤，标题带圈号：

```
① 装好它         命令行路径 / 副本数 / 残留；配置里的每个安装层都列出来（免管理员优先）
                 选一层 → 安装 / 重装 → 验证可用性
② 配好渠道和模型  配了官方接入说明的（Claude Code / OpenCode / Codex）直接照官方原文给步骤；
                 其余给渠道卡片 + 可复制的值。本工具不替你写这些配置文件
③ 启动 / 验证     启动（开窗口），或"跑一次冒烟"（让工具真的问模型一句话）
⌄ 维护与细节      全部安装位置、配置文件明细、清理残留、卸载
```

另外三个页面：**渠道**（九个渠道的注册入口、base_url、模型名、免费额度、实名/信用卡要求）、**诊断**（一键生成脱敏报告）、**历史**（每次真实改动的会话记录，可逐条还原）。

### 几个刻意的设计

- **没有"演练模式"开关**。点下去就是真的做，但每个改动型动作都会先弹**确认框**，框里是服务端给出的、即将真正执行的命令原文 —— 取消就什么都不发生。
- **配置以"自动写 + 官方步骤并存"**。Claude Code 那页可以直接把 `base_url` 与模型名写进 `settings.json`（只改受管的几个字段，写前备份）；
  其余工具仍然只给官方步骤和可复制的值。
- **key 永远不由本工具写**。没有真 key 时，那一项**不写**（绝不写 `<在这里粘贴你的 API Key>` 这种占位提示 —— 它会被当成真值用，实测直接把 Claude Code 弄挂）。
  要填 key 就自己填，或者存进环境变量（页面会告诉你变量名）。
- **key 不经手**。界面上那个输入框填的是**变量名**，不是 key 值；请求体里只有名字没有值（有测试钉着这一点）。
- **报告自动脱敏**。诊断报告里的用户名、路径、机器名会打码。

## 本地模型（Ollama）

这一章回答三件事：**你这台机器能跑多大**、**怎么下模型**、**能接进哪几个智能体**。

三条先说清：

- 本地模型是**换掉付钱的那一层**，不是换智能体。模型跑在自己机器上，Claude Code / OpenCode 这类工具还是原样用，只是它们连的地址从 `api.deepseek.com` 变成 `127.0.0.1:11434`。
- **本地没有 API Key 这回事。** 有的工具那个字段必填，随便填个占位（比如 `local`）就行，别把真实 key 填进去。
- **能力比在线 API 弱。** 省钱、离线、数据不出本机是它换来的东西，能力不是。

### 能跑哪一档

「本地模型」页会读你的显卡显存、内存、磁盘余量，然后逐档给结论：**能跑 / 能跑但慢 / 跑不动**，跑不动的那档直接告诉你为什么（显存差多少、磁盘差多少）。判定规则：

1. 磁盘按模型体积的 **1.5 倍**预检 —— 不够直接判跑不动，不管显存多大
2. 显存够 → 能跑（全量放显卡）
3. 显存不够但内存够 → 能跑但慢（退到 CPU，速度差一个数量级）
4. 内存读数拿不到 → **说不准**，而不是"跑不动"（不冤枉人）

显存读的是注册表里的真实值，不是 `Win32_VideoController.AdapterRAM` —— 后者是 32 位字段，超过 4 GB 一律报 4095 MB。

目录里现在有 6 档，从 2B 到 27B；每一档都标了体积、需要的显存、许可证，以及**实测能力**（含"这个模型到底会不会用工具"）。

### 下载与删除

- 下载走 Ollama 的流式接口，进度按 10% 一行；结束前会**回查已装列表**，不是只看命令有没有报成功。
- 删除**会真的删文件**，不搬备份区 —— 一个模型几 GB，搬备份很可能把磁盘撑爆。所以安全性来自"可重下 + 有账可查"：删了什么、多大、怎么装回来，记在 `out\state\model-removals.log`。
- 两条动作都走和安装一样的门禁：先 `preview` 拿服务端命令 → 弹确认框 → 只有 `-Apply` 才真动手。命令本身可以直接复制到终端重跑。

### 接进各智能体

| 工具 | 能直连 | 为什么 |
|---|---|---|
| OpenCode | ✅ | 它的配置就是 `@ai-sdk/openai-compatible` + `baseURL`，换成 `127.0.0.1:11434/v1` 即可 |
| Codex CLI | ✅ | 官方就支持自定义 `model_providers`（base_url + key） |
| DeepSeek Harness | ✅ | 官方支持「Custom model API」：`api: openai-completions` + `baseURL` + key 留空 |
| Claude Code | ❌ | 它只说 Anthropic 协议（`/v1/messages`），Ollama 给的是 OpenAI 协议，中间需要翻译代理 —— 这一版不做 |
| Gemini CLI | ❌ | 它的自定义端点走 Gemini 自己的协议，Ollama 不说这个协议 |

能直连的这三个，页面里给出**可复制的片段**与步骤，但**不代写**它们的配置：那些文件是嵌套结构，盲写很容易把你自己已有的渠道配置搞坏。配置片段与实测状态都在各智能体的页面底部「本地模型（可选）」一段里。

### 三个已知的坑（都实测过）

1. **默认上下文只有 4096，而且静默截断。** 实测：9630 字符的输入，`num_ctx=4096` 时只处理了 2050 个 token，不报任何错。所以本工具各处都用 32K。
2. **工具调用不一定真会。** 模型卡上写着 `tools` 不代表它会返回结构化工具调用 —— 实测 `deepseek-r1:7b` 就只把调用当普通文本吐出来。所以「本地模型」页有「自检工具调用」按钮：发一条带 `tools` 的请求，断言回来的 JSON 里真有 `tool_calls`。
3. **Ollama 报的模型体积不可靠。** 实测 `gemma4:26b` 的 `ollama ps` 显示 1.3 GB，清单里实际是 17.33 GB。所以磁盘占用按清单算，不按它显示的数字。

## 快速开始

### 需要什么

Windows 10 及以上、系统自带的 **PowerShell 5.1**、任意现代浏览器。不需要 Node、不需要管理员、不需要编译工具链。

### 三种启动方式

| 方式 | 怎么做 | 适合 |
|---|---|---|
| **源码直接跑** | 双击仓库根目录的 `LLMKit-web.bat` | 想直接看代码/改代码 |
| **绿色包** | 解压后双击 `LLMKit-web.cmd` | 只想要一个能用的工具 |
| **单文件** | 双击 `LLMKit-web-single-<日期>.cmd`（自解压） | 连解压都懒得做 |

三者都会：起一个本地服务（默认 `127.0.0.1:17800`，被占用会自动往上换）→ 自动打开浏览器。**关掉那个命令行窗口就停止服务**。

### 第一次用，建议这个顺序

1. 打开网页 → 顶部「刷新状态」看这台机器现在什么情况
2. 先进**配套工具**：装 Node.js（如果还没有）、Git；要写 Python 再装 Python / PyCharm
3. 去「渠道」页看一眼，挑一个渠道，在它的控制台**自己创建一把 Key**
4. 回**智能体**页：① 安装 → ② 照页面上的官方步骤配渠道 → ③ 启动，或点「跑一次冒烟」确认真能跑通
5. 出问题就进「诊断」页生成脱敏报告

## API Key 怎么流动

一句话：**环境变量只是 Key 的投递口，不是存放处。**

```
你在渠道控制台创建 Key
  → 存进本机环境变量（setx DEEPSEEK_KEY "sk-..."）
  → 引擎按"变量名"从环境里读一次值
  → 写进各工具自己的配置文件（那些工具只认自己配置文件里的明文 Key）
  → 工具启动时自己读它
```

本工具做的事只有中间两步：**读环境变量**、**把值写进工具自己的配置**。它不保存 Key、不上传、不代发。

## 安全边界（这部分请认真看）

- **只监听 `127.0.0.1`**：服务不对局域网/外网开放，也不走 CDN（前端所有资源都在本地）。
- **请求体只认白名单字段**：动作、工具 id、安装层 id 之类；**路径、命令、参数一律给不了**，全部来自服务端配置与检测结果。
- **改动前一定先给你看命令原文**，那条命令来自服务端的 `/api/preview`，不是界面自己拼的。
- **只搬不删**：被替换/移除的东西挪到备份区并写进会话日志，可在「历史」页还原。唯一的例外是卸载时你显式勾选"同时移除用户配置"，那一步会写明"这是真的删"。
- **第三方应用的私有数据库一律不写**：cc-switch 的供应商存在它的 SQLite 里，本工具只读不写。
- **仓库里不含任何本机信息**：有 `tests/Test-NoLeak.ps1` 守着（用你本机的用户目录/用户名反查仓库，换台机器也有效）。

## 已知限制（如实列出）

- **真机干净环境未完整验证。** 开发环境的出网被中间设备拦断，因此"从零下载安装"的链路只验证到"失败被准确识别并翻译成人话"这一层。
- **部分工具只给步骤，不给一键装。** Python / PyCharm 走官方安装器（本工具不替你静默运行第三方安装器）；Git / Node 的免管理员层需要联网下载。
- **有些配置是"给值不写"**：OpenCode 的嵌套 provider、dsh 的私有凭据、cc-switch 的 SQLite —— 盲写它们的风险高于收益，所以只给可复制的值。
- **Claude Code 连不了本地模型。** 协议不同（Anthropic vs OpenAI），需要一层翻译代理；这一版不做，页面上会明说，不给假希望。
- **本地模型的下载与删除在真机上验证过，但只在一种显卡上。** 实测机器是 RTX 3080 10GB；其它显存档位的"能不能跑"由判定规则推算，不是逐卡实测。
- **只做 Windows。** macOS / Linux 未适配。
- **界面只有浏览器一套。** 早期做过 WinForms 桌面版，已删除（维护两套界面的成本高于收益）。

### 打包

```powershell
powershell -File build\Build-Release.ps1 -Tier green+single -Zip
```

产出两个东西：绿色包（文件夹，脚本内容可直接查看）和单文件 `.cmd`（内嵌 base64 载荷，双击自解压）。两条都不需要编译器。

### 改代码时的几条硬规矩

- `.ps1` / `.psm1` 必须是 **UTF-8 带 BOM + CRLF**；`.md` / `.js` / `.json` / `.yml` 是 **UTF-8 无 BOM + LF**。PowerShell 5.1 读没有 BOM 的脚本会把中文全解成乱码。
- 改完跑一遍 `tests\Test-NoLeak.ps1` —— 它守的是"别把本机路径和 key 提交上去"。
- 危险动作必须显式开启：命令行默认**演练**（不带 `-Apply` 什么都不改），网页版靠**确认框**兜底。
